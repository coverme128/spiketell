更新时间：2026-10-10。**最新补充：v1.0.1 原包已核对，前台输入→准备→实盘验证入口已补齐，173 项后端/16 项浏览器通过；见 [个人实盘验证闭环](minute-only/implementation-report.md)。开机自启与后台提醒按用户要求延后。** 四场景 v1.0.2 已集成，详见 [本次实施报告](v1.0.2/implementation-report.md) 和 [F201–F228 矩阵](v1.0.2/issue-matrix.csv)。最初缺口审计保留在 [初始审计](IMPLEMENTATION_AUDIT_INITIAL.md)。本文描述最新代码，不把休市检查或回放等同于实盘验收。

## 已补齐的真实使用流程

1. 双击仓库根目录的 `启动 SpikeTell.command`（macOS）启动本机服务并打开浏览器；保留已运行实例。Windows 提供 `.cmd`，尚未在 Windows 真机验收。
2. 首页确认数据源个人使用范围。该操作只记录用户声明，不能代替数据源授予权限，也不会直接把行情设为已校准。
3. 搜索真实证券名称/代码，或批量添加；正式服务调用真实个股资料核验，不存在或不可取得资料的代码会明确拒绝。自动加载名称、上市日、板块、风险标签和源提供的涨跌停价。
4. 在真实当日报价尚未证明有成交时，证券保持等待状态；当日新鲜交易与有效分钟共同放行。ST、新股、退市名称、缺失资料和陈旧数据继续阻断。
5. 自动准备新浪历史成交额；历史原始记录单独存储，没有捏造东财缺失的历史开盘价。时间语义未经核验时这些基准不参与 HIGH 计算。历史价格与当日昨收参考明显不符时保留审计并停用跨日基准。
6. 交易时段自动对照两股、两源及带时间戳的实时报价：要求观察变化的分钟数据、成交额增量与报价增量吻合，再验证收盘后稳定的分钟及跨源一致性。没有观察到足够变化就继续等待，不凭静态标签放行。
7. 生产采集采用有界 curl 传输、共享并发/请求预算、单股断路器、429 退避、响应字节限制。分钟必须在收盘后两次观察一致才交给规则；有修订则重新等待确认并保留 correction。
8. 自选池连续三轮实际采集达到覆盖/时延要求后，仅放行已验证规模；扩池后重新检查。该检查不等于 50 股两个完整交易日发布验收。
9. 已有规则、Episode、去重与 SSE 接通该流程；新规则版本为 `spike_rules_v1.0.2`，历史事件保留旧版本。通知只在授权、页面可见、非安静模式且事件允许时尝试发送。

## 本次补齐的测量、产品和运行能力

- 覆盖率按股票×分钟记录，未知元数据仍留在分母；只允许有证明的停牌排除。包含逐股缺失清单、完整 50 股交易日识别及 p50/p95。
- 浏览器可见心跳和提醒回执关联；应呈现却缺回执的提醒保留为缺失，不能只统计成功回执后宣称达标。
- 活动时间/重要性排序、完整历史 JSON/CSV、卡片更新时刻、参考高点与回落数值、忽略提醒、详情随事件刷新；修复活跃卡重复出现在历史区。
- 过往历史清理先备份，保留今天事件和去重状态；默认 90 日可调保留、每日一致性备份、最近七个常规备份。
- 版本化 SQLite 迁移（001→002→003→004）保留原数据；macOS launchd 安装/卸载脚本与可审阅模板；没有未经请求替用户安装系统服务。
- 10 秒 SSE 退出排空上限，单实例保护。采集/准备/维护分别处理失败，NTP 暂时失败不阻止独立资料准备，但会阻断信号。

## 实际证据与边界

- [正式 HTTP 真实联网检查](real-http-integration.json)：空配置启动，自动取得日历和 NTP；两只真实股票通过正式添加接口取得名称及九日历史，生产数据库未加入测试股票。
- [真实准备检查](real-preparation-check.json)：真实证券搜索，两股各获取九个历史交易日；候选 end 归一化取数成功。此文件生成时未校准，原始待校准标签统计不代表可用基准数量；新版界面只计已校准的连续竞价槽位。
- [真实历史回放](real-history-replay.json)：四股各 1,970 行。实际价格、成交额不变；为测试引擎使用明确标注的虚拟回放时钟，所有事件为 SIMULATION，未写入生产库或发送 LIVE 通知。
- [后端报告](backend-tests.xml) 173 项通过、[浏览器报告](browser-tests.xml) 16 项通过，另有原规格 8 项通过：包含单元、集成与真实浏览器交互。注入行情/时钟测试不伪称现场交易样本。
- [退出检查](sse-shutdown-check.json)：独立 SSE 客户端保持连接时完成生命周期退出、释放锁且数据库正常。
- [发布门禁](release-gates.json)：仍保留不足证据状态。界面存在、真实接口可达、自动化测试通过均不等于个人实盘已验收。

## 交付前仍须完成的真实验收

今天为休市日，不能现场证明下一交易时段的分钟标签、最终化和 50 股表现。自动校准逻辑已经实现并有注入集成测试，但尚未成功完成一轮真实盘中校准；若源不满足观察条件，它会明确等待/报错，而不会绕过检查。

还需：源使用范围核验；在目标设备、真实自选池完成盘中校准和吞吐检查；50 股至少两个完整正常交易日，覆盖率 ≥95%、收盘至可见提醒 p95 ≤45 秒；真实 OS 通知授权/拒绝/后台/点击；带活跃 Episode 的异常退出和恢复；目标机自启动验证。无通知样本时 p95 保持空值。

因此当前是**真实接入流程已实现、等待盘中验收的交付候选版**，不能标为 PERSONAL_RUNTIME_READY，也不能向用户保证已经验证实盘稳定性。
