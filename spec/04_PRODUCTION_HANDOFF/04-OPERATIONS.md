# 04 — Operator Runbook & Maintenance

## 上线前

创建 Python 虚拟环境、安装锁定依赖、复制 `.env.example` → 本地 `.env`、设定交易日历源、验证行情数据源许可及 Token（不提交到仓库）、运行 migration、单机单实例启动，检查 `GET /api/v1/health/ready`。

## 每天开盘前

检查上一交易日日期、交易所日历、NTP、Provider 资格、watchlist 有效股数量、最近 K 线基线是否准备完成。不能以今天“周五”推断一定开市。

## 盘中

- `HEALTHY`：观察最新 final bar 时间、50 股票覆盖、从 bar_end 到收到/呈现的延迟分布。
- `DEGRADED`：明确哪些股票没有有效数据、跳过它们的高优先级提醒；减少股票池不是自动解决数据源能力不足的发布验证。
- `STOPPED`：暂停新机会/桌面通知；保留历史卡并加过期标签；人工检查网络、限流、Provider 更改、权限、系统时钟。

## 收盘与历史

归档完整事件与使用规则版本；只保留事件履历及轻量诊断，无盈利预测输出；SQLite 做一致性检查与定期备份。重启后读取数据库与 Last-Event-ID，旧事件只补 UI 不触发桌面通知。

## 常见故障排查

| 现象 | 可能原因 | 操作 |
|---|---|---|
| 一直没有 Spike | 当前没达到阈值/交易休市/数据源断线 | 看 Session、Feed Health、阈值版本，不临时大幅降低阈值制造卡 |
| 突然大批量 Spike | 单位转换错、数据重放、复权价格混入、时钟偏移 | 立即停发，检查 bar 与归一化日志 |
| 同一股票卡片重复 | 去重事务或 episode_id 不稳定 | 检查唯一约束、事务和双 worker |
| 浏览器没提示 | 页面关闭/权限拒绝/OS DND/SSE 断线 | 测试权限与页内 toast，不向用户保证后台推送 |
| 收盘时仍“监控中” | session guard 逻辑错误 | 关闭新 Trigger，修复时段配置 |
| 中午发现3m Spike | 跨午休计算窗口 | 修复连续交易分钟判定 |

## 后续版本决策条件

先验证真实用户是否减少盯盘、延迟与重复提醒是否合格；只有显著可用性数据才考虑更深入的 Spike Quality/买入时机。V1 不先预建预测模型、自动交易与 SaaS 权限层。
