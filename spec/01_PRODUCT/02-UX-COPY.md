# 02 — UX, Wireframes & Copy Contracts

## 1. 信息层级

`Feed Health`（可信性） > `Top High Spike`（重要对象） > `为何入选`（可理解） > `进展`（现在还有效吗） > `全部自选股`。不要把所有价格指标、历史回测或 K 线堆在首页。

```text
┌──────────────────────────── Radar ───────────────────────────────┐
│ 连续竞价 · 最新完整分钟 10:05 · 可用 46/50 · 通知已授权           │
│ 监控 50     今日 Spike 8     当前重点 2                        │
│ 重点关注（按优先级；最多三张）                                   │
│ ┌─ 股票 A 600000.SH ────── HIGH / NEW ─────────────────────┐     │
│ │ 1m +1.2%   成交额 4.0x   3m +1.9%                      │     │
│ │ 放量 | 刷新区间高点 | 连续上涨                          │     │
│ │ 建议：立即查看走势    K 线截至 10:05                    │     │
│ └──────────────────────────────────────────────────────────┘     │
│ 股票 B — MEDIUM / ACTIVE ...                                    │
│ 展开全部异动   今日活动   管理自选股                              │
└───────────────────────────────────────────────────────────────────┘
```

## 2. 每张卡必含信任信息

显示 **行情截至** (`bar_end_at`) 与 **系统收到** (`received_at`)，两者语义不同。数据源健康失效时卡片覆盖 “历史信号，不可作为最新异动依据”；不能沿用绿色 Live 标签。

优先级中文：HIGH = `重点异动`，MEDIUM = `一般异动`，LOW = `仅记录`。状态中文：NEW = `刚刚触发`，ACTIVE = `持续监控`，STRENGTHENING = `动能增强`，WEAKENING = `动能减弱`，EXPIRED = `异动结束`，INVALIDATED = `数据校正/无效`。

动作文案：`立即查看走势` / `继续观察` / `忽略该提醒`。**不得在 UI 内等同于买入按钮或给出隐含投资建议。**

## 3. 空状态与错误文案

- 空列表：`当前没有达到重点提醒条件的异动`。副文：`系统仍在监控已启用的自选股。`
- 不在交易时间：`当前非连续竞价时段，已暂停新异动检测。`
- 权限未授予：`浏览器通知未开启。页面打开时仍可看到提醒；关闭页面后不会收到系统推送。`
- 过期：`行情延迟，已暂停新的重点提醒；最近完整 K 线截至 HH:MM。`
- 部分不可用：`本轮仅 XX/YY 只股票行情有效；其余已暂停提醒。`
- 基准不足：`成交异常倍数暂不可用：有效历史不足。`
- 离线恢复：`行情已恢复，将只提醒恢复后的新触发异动。`

## 4. 通知设计

标题：`重点异动 | 股票名 (代码)`；正文：`1m +1.2% · 成交额 4.0× · 截至10:05 · 点击查看`；次级文本写 `异动提醒，不是买入建议`；由 OS 浏览器决定是否能显示第二行。`episode_id` 指向唯一详情页。相同 `episode_id+alert_kind+rule_version` 不可重复通知。

## 5. 性能与响应设计

卡片首次渲染显示内容骨架，但未连接真实 Feed 时不得用模拟数据伪装 Live。桌面 Top1 显著但不夸张；移动端一列；分数不是胜率，不大字写 `85%`。每次状态变化不整体重排导致用户失焦：仅在高优先级新信号时提升位置，并保持焦点键稳定。
